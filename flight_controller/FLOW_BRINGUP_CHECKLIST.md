# フロー (PMW3901) 立ち上げチェックリスト  — drone_s5 / POSHOLD

最終更新 2026-09-09。高度ホールド (ALTHOLD) は LOG0060 で完成済み。
残りは **フローの復活** と **POSHOLD まで**。

## Phase 0 — 前提 (これができていないと先に進めない)

- [ ] **M4 の推力非対称を確認/対処**
  - LOG0060 で `M4/M1 = 1.93`、pitch の仕事量が roll の 3 倍、穏やかなホバーで既に権限に 3.7% 張り付き
  - POSHOLD はフローが姿勢目標 (最大リーン 8°) を出すので、pitch の余力不足だと位置保持がふらつく/発散しうる
  - 傾斜計を各モーター上面に当てて M4 が 2〜3°以上ズレていないか。ズレていればアーム/マウント調整
  - どうしても後回しにするなら「POSHOLD は穏やかにしか効かない」前提で進める
- [ ] **`USE_FLOW = true` にしてビルド** ([drone_s5.cpp §2](src/drone_s5.cpp))
  - `USE_SD` が自動で false になる (SPI0 競合回避)。ログは RAM + USB `'l'` のみ
- [ ] **ファーム書き込み** (`pio run -e drone_s5 -t upload`、Teensy 接続確認)
- [ ] ゲインは LOG0060 時点 (= 飛べていた値) に戻っていること
  - `RATE_*` ki=0 / `RATE_D_ALPHA`=0.80 / `ANG_*` ki=0.04

## Phase 1 — PMW3901 を応答させる (現在の最大ブロッカー)

今日の全ログで `flow_ok=0`。まずここ。

- [ ] **配線確認**: CS = `FLOW_CS_PIN`(既定 **10**)、SCK=13 / MOSI=11 / MISO=12、電源 (3.3V)
  - CS ピンが実配線と違うなら `FLOW_CS_PIN` を直す
- [ ] 起動 → シリアル画面の **`[フロー]` 行** (新設) を見る
  - `OK` → Phase 2 へ
  - `FAIL(起動時に応答なし)` → 下へ
- [ ] **SPI0 競合の切り分け**: `USE_FLOW=true` なら firmware は SD を init しないが、
      **HW-125 モジュールが物理的にバスに刺さっているだけで** 74LVC125 が MISO を
      駆動して PMW3901 を潰すクローンがある
  - [ ] SD モジュールを**コネクタごと物理的に外して**起動 → `[フロー] OK` になるか
    - なる → HW-125 の MISO バッファが犯人。恒久対策: MISO に直列抵抗 / 74LVC125 の
      4 回路目で CS ゲート / SD を別 SPI バスへ
    - ならない → PMW3901 本体か配線か電源。`'d'` のデバイスチェックも確認
- [ ] 機体を手で動かして `[フロー] 生カウント(x,y)` が変化するか (0 のまま動かなければ死んでいる)

## Phase 2 — s5a ベンチ校正 (プロペラ外す / `'m'` ドライラン ON)

`QuadConfig.h §7` の手順どおり。RAM ログは `'n'` で 8 秒手動トリガ → `'v'` でダンプ。

- [ ] **軸の入れ替え**: 機体を手で「前」へ平行移動 → `flow_dx` が大きく動くか
  - 前後に動かして `flow_dy` が動くなら `FLOW_SWAP_XY = true`
- [ ] **符号**: 前進で `flow_dx` が **+**、右移動で `flow_dy` が **+** になるように
      `FLOW_SIGN_X` / `FLOW_SIGN_Y` (現在ともに -1.0)
- [ ] **de-rotation**: 機体をその場で傾ける (並進させない)
  - `flow_dx` / `flow_dy` がほぼ 0 のまま → OK
  - 逆に振れる → `FLOW_DEROT_SIGN_X/Y` を反転
- [ ] **`FLOW_PX_PER_RAD` の実測** (現在 450.0 = 仮値):
  1. `'h'` で実測高度 `h` [m] をセット (床からレンズまで)
  2. `'z'` で積算ゼロ
  3. 既知距離 `D` [m] を 1 方向にゆっくりスライド
  4. `flow_accx`(または accy)の生 raw 積算を読む
  5. `FLOW_PX_PER_RAD = (積算raw ÷ D) × h`
  - 桁で外れていると de-rotation も速度換算も桁でズレるので必須
- [ ] 値を `QuadConfig.h` に反映 → 再ビルド → 再確認

## Phase 3 — s5b 速度・位置ホールドのベンチ確認 (プロペラ外す / `'m'` ドライラン)

- [ ] `'p'` メニューでゲインが載っているか確認
  - `[i]` Vel P (`FLOW_VEL_KP` 6.0) / `[j]` Vel I (`FLOW_VEL_KI` 2.0) / `[o]` Pos P (`FLOW_POS_KP` 1.0)
- [ ] ドライラン中に **スティックを 35% 以上** (フロー制御は `thr > FLOW_ENABLE_THR` かつ
      離陸検知でしか出力しない。`FLOW_REQUIRE_AIRBORNE=true`)
  - 測距が無い/失探だと離陸検知が立たないので、Phase の測距が生きていること
- [ ] SW_HOVER=up (POSHOLD) にして機体を手で「前」へ動かす
  - `fh_leanp`(目標ピッチ) が **後ろへ戻す向き** (前に流れたら前傾せず後傾) に出るか
  - 符号が逆なら位置がすっ飛ぶので、ここで必ず止める
- [ ] `poshold.badCount()` (失探カウンタ) が地上で暴れていないか

## Phase 4 — 初回 POSHOLD フライト

- [ ] **広い床 / テクスチャのある面**(単色フローリング・光沢面は不可)、**明るさ十分**
- [ ] 低空 (30〜50cm)。天井が近いと測距が化ける
- [ ] 指をモードスイッチに。**SW_HOVER=down で bail-out (即 ANGLE)**
- [ ] アームは **必ず SW_HOVER=down (ANGLE 側)** で (POSHOLD 側だと `armGateOk()` が拒否)
- [ ] 手順:
  1. ANGLE で離陸、安定ホバー
  2. 高度が落ち着いたら **SW_HOVER を up** → POSHOLD 突入
     - この瞬間が RAM トリガ (今回追加。ここから 8 秒録れる)
  3. スティック中立で放置 → 位置が保持されるか
  4. 流れ始めたら即 **SW_HOVER=down** で ANGLE に戻して手動回収
- [ ] フローが死んだら自動で ALTHOLD に落ちる (`selectMode` の `suspectDead()` 判定)。
      画面の MODE 表示で確認

## Phase 5 — 解析

- [ ] 着陸・ディスアーム後、USB を挿して **`'v'`** で RAM ダンプ (`logger.py` で受ける)
- [ ] `python scripts/analyze_log.py logs/log_NNN.csv` で:

  - `fh_posn/pose` (地面固定フレーム位置) がドリフトし続けていないか

  - 姿勢ループ (`[5]`) が POSHOLD 中も落ち着いているか (pitch の 16.7Hz が悪化していないか)
